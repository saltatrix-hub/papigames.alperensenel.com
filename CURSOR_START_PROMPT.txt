# CURRENT PRIORITY

DO NOT focus on multiplayer, backend, networking, database, quests, economy, balance, or other large gameplay systems yet.

The current priority is to establish the complete character asset and animation pipeline for all six playable classes:

1. Knight
2. Berserker
3. Assassin
4. Ranger
5. Mage
6. Priest

The goal is to prepare ASTRAYA so that every class can have:

* unique character visuals
* four-direction movement
* walking animation
* idle animation
* basic attack animation
* class-specific combat animation
* skill/cast animations
* equipment visual layers
* weapon visual layers
* skill effect sprite sheets

Do NOT destroy or replace the existing LPC rendering system unless absolutely necessary.

Use the current LPC system as the foundation where possible.

---

# CORE CHARACTER DIRECTIONS

Every playable character asset must support:

* front / down
* back / up
* left
* right

Do not create a system that only supports front-facing characters.

The four-direction system is mandatory.

# RECOMMENDED FRAME TARGETS

Unless the existing LPC source requires a different frame structure:

Idle:
4 frames per direction

Walk:
8 frames per direction

Basic melee attack:
6–8 frames per direction

Bow attack:
8–13 frames per direction

Spell cast:
7–8 frames per direction

Hit:
3–4 frames per direction

Death:
6–8 frames

Do not blindly recreate assets if compatible animation sheets already exist.

First inspect the existing LPC sheets.

---

# ASSET ARCHITECTURE

We do NOT want one completely baked character sprite sheet for every equipment combination.

The character must eventually use layered rendering.

Recommended layers:

1. body
2. legs
3. feet
4. torso / armor
5. shoulders
6. gloves
7. hair
8. helmet / hood
9. cape / back item
10. main-hand weapon
11. off-hand weapon / shield / tome
12. additional cosmetic layer
13. temporary combat effects

Equipment visuals must remain separate from gameplay stats.

Preferred flow:

equipped item
→ visual ID
→ character visual descriptor
→ sprite layers
→ animation renderer

---

# EQUIPMENT REQUIREMENTS

The system must be capable of supporting changing equipment visuals.

Example:

Knight Level 1 sword

must be visually different from:

Knight Level 5 sword

and:

Knight Level 10 sword

The same principle should later work for:

* swords
* axes
* daggers
* bows
* staffs
* maces
* shields
* tomes
* helmets
* chest armor
* gloves
* boots
* capes
* costumes

Do NOT create separate complete character sprites for every possible equipment combination.

Equipment must be composable.

# SPRITE SIZE

Inspect the current LPC system before choosing dimensions.

The current LPC pipeline appears to use 64×64 source frames.

Do NOT arbitrarily change this without verifying the renderer.

Document:

* source frame size
* rendered size
* anchor point
* character foot position
* weapon pivot expectations
* frame origin
* direction row order

The body and all equipment layers must align pixel-perfectly.

---

# RIGHT / LEFT DIRECTION RULE

Determine whether left and right require separate sprite artwork or whether selected layers can be mirrored safely.

Weapons, shields, asymmetrical armor and directional effects may require dedicated left/right logic.

Do not assume every sprite can simply be mirrored.

Document the final rule.

---

# ART GENERATION LIMIT

Do not pretend that production-quality final character artwork exists if it does not.

* clearly mark missing art

The purpose of this task is to make the project READY for consistent asset production and integration.
